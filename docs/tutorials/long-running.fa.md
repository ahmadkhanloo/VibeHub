# آموزش کار با دستیارهای کدنویسی

راهنمای کوتاه برای برنامه‌ریزی، انتخاب مدل و بررسی کار دستیار.

این مخزن مشخصاً نمونه‌ای آموزشی برای Claude Code است، نه ابزار آماده‌ای که بی‌تغییر در هر دستیار کار کند. الگوهای مفیدش شامل معیار پایانِ پیش‌فرضِ ناموفق تا دیدن مدرک، ارزیاب جدا با زمینهٔ تازه و ثبت پیشرفت برای تحویل به جلسهٔ بعد است. نویسندگان آن را مواد نمونهٔ رویداد Code with Claude معرفی می‌کنند؛ برای ابزار دیگر باید ایده‌ها را اقتباس کرد، نه اینکه هوک‌هایش را کورکورانه کپی کرد.

## پایان را دقیق تعریف کن

معیارهای پذیرش را پیش از شروع بنویس؛ هیچ‌کدام تا دیدن مدرک، انجام‌شده نیست.

## هر نوبت یک گام

هر بار یک بخش کوچک و کامل را تمام کن تا پیشرفت قابل‌بررسی بماند.

## نتیجه را با مدرک بسنج

اجرای واقعی، تصویر یا گزارش را بررسی کن؛ فقط به ادعای عامل اکتفا نکن.

## وضعیت ادامه را ثبت کن

تغییرها، بررسی‌ها و قدم بعدی را کوتاه بنویس تا جلسهٔ بعد از همان‌جا شروع شود.

## چند پیشنهاد کاربردی

- برای تغییر چندفایلی، اول هدف و معیار پایان را بنویس و از دستیار بخواه پلن کوتاهی ارائه کند؛ پس از بررسی پلن، اجرا را شروع کن.
- سطح استدلال پایین برای سؤال و تغییر کوچک، متوسط برای کار چندفایلی معمول، و بالا برای طراحی دشوار یا عیب‌یابی پیچیده مناسب است. سطح‌های بالاتر ممکن است زمان و هزینه را زیاد کنند.
- پس از تغییر، diff و نتیجهٔ آزمون را بخوان. برای کار چندجلسه‌ای، وضعیت، کارهای مانده و گام بعدی را در یک فایل پروژه ثبت کن.

## دستور آماده

هدف و معیارهای پایان این کار را اول خلاصه کن. اگر کار چندبخشی است، پلن کوتاهی پیشنهاد بده و تا روشن‌شدن ابهام‌ها شروع نکن. کار را به گام‌های کوچک تقسیم کن؛ نتیجهٔ واقعی هر معیار را بررسی کن و بدون مدرک انجام‌شده علامت نزن. در پایان، تغییرها، آزمون‌ها، موارد باقی‌مانده و قدم بعدی را در PROGRESS.md ثبت کن.
