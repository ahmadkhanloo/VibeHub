درس ۲ از ۳ · زمان پیشنهادی: ۲۵ تا ۳۵ دقیقه، همراه تمرین

در پایان می‌توانی تغییرات دستیار را بررسی کنی، روی شاخه ثبت کنی و به GitHub بفرستی.

## کار محلی با ایجنت

در پوشهٔ تمرینی درس قبل ادامه بده. وضعیت اولیه را بخوان؛ تغییرهای قبلی را ابتدا بررسی و جداگانه ثبت کن تا با کار جدید مخلوط نشوند:

```powershell
git status
```

شاخهٔ مستقل برای تمرین بساز:

```powershell
git switch -c practice/agent-note
```

نام شاخهٔ فعلی باید practice/agent-note باشد:

```powershell
git branch --show-current
```

یک خط توضیح به notes.txt اضافه کن، خودت یا با کمک دستیار. تغییرها را بخوان و فایل را در ویرایشگر بررسی کن؛ در پروژهٔ واقعی آزمون‌های مرتبط را نیز اجرا کن:

```powershell
git diff
```

فقط فایل بررسی‌شده را انتخاب کن:

```powershell
git add notes.txt
```

دقیقاً محتوایی را ببین که قرار است ثبت شود:

```powershell
git diff --staged
```

با پیام مشخص ثبت کن:

```powershell
git commit -m "Clarify practice notes"
```

درخواست آماده برای دستیار:

> تغییر خواسته‌شده را انجام بده، دلیل تغییر و نتیجهٔ بررسی‌ها را بگو و diff را برای بازبینی آماده کن. فقط اگر درخواست کردم کامیت یا push کن.

فایل `.gitignore` نام فایل‌های خارج از رهگیری، مانند `.env`، را مشخص می‌کند؛ فایل قبلاً ثبت‌شده را از مخزن یا تاریخچه حذف نمی‌کند. رمز و کلید را وارد کامیت نکن.

## ارسال و همکاری در GitHub

در GitHub یک مخزن آزمایشی خالی با نام git-practice بساز؛ README یا فایل اولیه اضافه نکن. [راهنمای رسمی احراز هویت؛ بازکردن در مرورگر](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github) را دنبال کن؛ نام و ایمیل Git ورود به حساب نیستند.

نشانی زیر را با نشانی مخزن خودت جایگزین کن؛ این فرمان مقصدی با نام origin اضافه می‌کند:

```powershell
git remote add origin https://github.com/YOUR-USERNAME/git-practice.git
```

پیش از ارسال، مقصد را بررسی کن:

```powershell
git remote -v
```

شاخهٔ پایه را بفرست:

```powershell
git push -u origin main
```

شاخهٔ تمرین را هم بفرست؛ گزینهٔ -u ارتباط شاخهٔ محلی با شاخهٔ راه دور را تنظیم می‌کند:

```powershell
git push -u origin practice/agent-note
```

fetch اطلاعات راه دور را دریافت می‌کند؛ pull دریافت را با ادغام در شاخهٔ فعلی همراه می‌کند؛ push کامیت‌های محلی را می‌فرستد. قبل از pull تغییرات محلی را بررسی کن؛ ادغام ممکن است تعارض ایجاد کند.

در GitHub یک Pull Request از practice/agent-note به main باز کن. diff را بخوان و پس از بررسی merge کن. [بازبینی کد](/learning/code-review) ادامهٔ اختیاری است.

افزونهٔ GitHub در ابزار هوش مصنوعی فقط یک اتصال با مجوز حساب است؛ جای خود Git یا بررسی تغییرات را نمی‌گیرد.

## وقتی اشتباه کردی

- فایل اشتباهی stage شده: `git restore --staged notes.txt`؛ ویرایش فایل باقی می‌ماند.
- تغییر محلی نامطلوب: اول diff را بخوان. `git restore notes.txt` تغییر ثبت‌نشدهٔ همان فایل را حذف می‌کند؛ فقط وقتی اجرا کن که آن تغییر را نمی‌خواهی.
- کامیت منتشرشدهٔ اشتباه: `git revert HEAD` یک کامیت جبرانی می‌سازد؛ ابتدا مطمئن شو HEAD همان کامیت موردنظر است. برای خروج از ویرایشگر پیام کامیت باید پیام را ذخیره کنی و ویرایشگر را ببندی.
- conflict: توقف کن، status و فایل‌های تعارض را بخوان و هر دو تغییر را بررسی کن؛ بدون فهم نتیجه «قبول همه» را انتخاب نکن. برای ادامه از بخش رفع مشکل درس بعد کمک بگیر.
